# AutoDoc

Status: Current focus: project-status journaling, README-first visibility, and living project summaries

## Project story
AutoDoc is now being used as a lightweight project operating system: keep the README as the quick landing page, keep a `project-status.md` as the live journey log, and keep the short completion file as the current snapshot of what matters most right now. The latest focus is not just capturing work, but making the project story easy to read and easy to update after every session.

## What matters most right now
- The short project summary is intentionally overwritten with the latest status, not kept as a stale static page.
- The long summary keeps the broader history, trials, lessons, and significant contributions over time.
- The README and project-status file are the two main surfaces for quick human review.
- Each finish now records the current narrative and preserves the longer project story for future context.

## Lessons learned
- The short file should be the current view, not a historical archive.
- The long file should preserve the story, trials, and why the project evolved.
- README-first visibility makes the project easier to understand at a glance.
- AI output is best when it is treated as a current draft that gets grounded in actual logs and evidence.

## Next steps
- Keep the short file refreshed after every project update.
- Use the long file as the main accumulation of lessons, friction, and contributions.
- Keep the public-facing project docs simple, readable, and current.
- Continue improving the status-file workflow across active repos.
